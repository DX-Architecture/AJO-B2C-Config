A FastAPI HTTP service (locsync-translation/) that translates

Translation is a multi-step pipeline, not a single instant lookup.

Core ideas: 
1.​ Chunks, not blobs — Text arrives as a dictionary of { "id": "text" }. IDs let the caller 
map results back to UI elements or subtitle cues. 
2.​ Async by design — Gemini and AutoML calls can take seconds. The API returns 
immediately with a job_id so callers never block on model latency. 
3.​ Quality layers — Raw machine translation can be refined by Gemini using 
language-specific rules loaded from Google Sheets (PE rules, personas, DNT lists). 
4.​ Content-type routing — The same API endpoint behaves differently when content_type 
is "Video subtitle (SRT)" vs. generic text.

3.1 Authentication 
Every protected endpoint requires a pre-shared token: 
X-Api-Token: <your-token> 
The server validates the token using SHA-256 hashing + constant-time comparison 
(hmac.compare_digest). The raw secret is stored only in the MT_API_KEY environment variable 
— never logged or returned. 
HTTP status

Missing or invalid X-Api-Token 
429

4. How Translation Works Internally 
4.1 Standard Workflow 
Used for most text — including Adobe Express canvas text overlays when content_type is not 
SRT-specific. 
flowchart TD 
    START[Job started] --> VALIDATE[Validate method & language 
pair] 
    VALIDATE --> DNT{enable_dnt?} 
    DNT -->|Yes| FETCH_DNT[Load DNT prompt from Sheets] 
    DNT -->|No| ENGINE 
    FETCH_DNT --> ENGINE{engine_type} 
 
    ENGINE -->|google| MT[Parallel AutoML per chunk] 
    MT --> STYLE1{method ends with +style?} 

--- PAGE 9 ---
None‎
    STYLE1 -->|Yes| PE1[Gemini style correction] 
    STYLE1 -->|No| DONE1[Return machine_translations] 
    PE1 --> DONE2[Return translations + changes] 
 
    ENGINE -->|gemini| GEM[Gemini translate_batch with PE rules] 
    GEM --> DONE3[Return translations + changes] 
PE rules injection: Before calling Gemini, the backend loads: 
●​
Universal rules (all content types) 
●​
Language-specific rules (per target language column in AI PE Sheet) 
●​
Content-type persona and style guides (when applicable) 
●​
SRT-specific rules (when content_type == "Video subtitle (SRT)") 
Rules are cached on disk (/tmp) and refreshed via POST /refresh_rules or pod restart. 
4.2 SRT Subtitle Workflow 
When content_type is "Video subtitle (SRT)", a two-phase pipeline runs instead of 
per-chunk MT: 
flowchart TD 
    S1[Phase 1: Concatenate all cue texts] --> S2[Translate full 
paragraph<br/>Google or Gemini] 
    S2 --> S3{method ends with +style?} 
    S3 -->|Yes| S4[Phase 2: Gemini rebalance<br/>Map translation 
back to timecodes] 
    S3 -->|No| S5[Split Phase 1 output per cue] 
    S4 --> S6[Store in translations + srt_output] 
    S5 --> S6 
Why two phases? Subtitle cues are short fragments. Translating each cue in isolation loses 
sentence context. Phase 1 translates the full paragraph; Phase 2 (Gemini) redistributes the 
translation across original cue boundaries using SRT-specific rules from Google Sheets. 
Chunk ID convention for SRT: chunk_0, chunk_1, … plus optional _srt_source metadata key. 
Adobe Express caveat: The built-in Caption Video feature produces a burnt-in caption layer. The 
Add-on SDK cannot read timed caption track data today. The SRT workflow is most relevant when 
the add-on (or Plan B) sends pre-parsed SRT cue text as chunks.

Recommended add-on steps: 
1.​ Read — Use allTextContent or selection APIs to collect { nodeId: text }. 
2.​ Map — Convert node IDs to chunk keys (e.g. "node_abc123": "Hello world"). 
3.​ Translate — POST to LocSync with content_type: "Video subtitle (SRT)" when 
translating subtitle-like text. 
4.​ Poll — Adaptive interval: 1 s for first 10 polls, then 2–3 s (same pattern as 
LocSync/app/translation/translation_engine.py).

5.3 Example: Add-on UI iframe (JavaScript) 
const API_BASE = "https://your-locsync-api.example.com"; 
const TOKEN = await 
addOnUISdk.clientStorage.getItem("locsync_token"); 
 
async function translateChunks(chunks, sourceLang, targetLang) { 
  const startResp = await 
fetch(`${API_BASE}/translate_chunks_start`, { 
    method: "POST", 
    headers: { 
      "Content-Type": "application/json", 
      "X-Api-Token": TOKEN, 
    }, 
    body: JSON.stringify({ 
      source_lang: sourceLang, 
      target_lang: targetLang, 
      chunks, 
      method: "gemini+style", 
      content_type: "Video subtitle (SRT)", 
    }), 
  }); 
  if (!startResp.ok) throw new Error(`Start failed: 
${startResp.status}`); 
  const { job_id } = await startResp.json(); 
 
  for (let i = 0; ; i++) { 
    await sleep(i < 10 ? 1000 : i < 30 ? 2000 : 3000); 
    const statusResp = await fetch( 
      `${API_BASE}/translate_chunks_status/${job_id}`, 
      { headers: { "X-Api-Token": TOKEN } } 
    ); 
    const data = await statusResp.json();

5.4 Example: Document Sandbox (JavaScript) 
import addOnSandboxSdk from "add-on-sdk-document-sandbox"; 
const { runtime } = addOnSandboxSdk.instance; 
 
async function applyTranslations(translations) { 
  const sandboxApi = await runtime.apiProxy("documentSandbox"); 
  for (const [nodeId, translatedText] of 
Object.entries(translations)) { 
    await sandboxApi.setNodeText(nodeId, translatedText); 
  } 
} 
 
// Exposed to UI iframe via runtime.exposeApi() 
runtime.exposeApi({ applyTranslations });
